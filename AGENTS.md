# AGENTS.md

Static portfolio site for a wood and glass business. Hugo + the `gallery` theme (git submodule), served from
Cloudflare at <https://woodand.glass>. Human docs: [CONTRIBUTING.md](./CONTRIBUTING.md).

## Commands

```sh
mise install                              # once; installs the pinned toolchain
mise run setup                            # once; installs the git hooks
git submodule update --init --recursive   # once; the theme is a submodule
mise run serve                            # dev server on http://localhost:1313
mise run check                            # lint + build
mise run build                            # build only
mise run lint                             # lint only
```

Run Hugo through mise. `mise.toml` pins `hugo-extended`, and a plain Hugo cannot build the theme's SCSS.

## Verify your change

There are no unit tests; the build is the test.

1. `mise run check` passes: lint clean, build exits 0 with no errors or warnings you caused.
2. For layout, CSS, or content changes, open `mise run serve` and look at the rendered page.

## Layout

- `data/events.yaml` — events list, rendered by `layouts/partials/events.html`. Dates are ISO 8601 with offset
  (`2026-04-18T09:00:00-04:00`). Events are the most common edit: keep the existing shape, and take dates and venues
  from the user rather than inventing them.
- `content/wood/`, `content/glass/` — galleries. Images sit beside each `index.md`. Hugo resizes them, so keep
  originals web-sized.
- `content/_index.md` — home page text.
- `layouts/` — template overrides for the theme. Change the site here.
- `assets/css/custom.css` — styles.
- `hugo.toml` — site config. `wrangler.toml` — Cloudflare config.
- `static/` — favicon and logo, served from the site root.
- `themes/gallery` — submodule. Override it in `layouts/`, never edit it in place.
- `public/`, `resources/` — generated by the build. Edit sources, not these.
- `.gitmodules` — carries a stale `hugo-myportfolio-theme` entry. Leave it.

## Deploy

Cloudflare publishes `public/` (Worker `wood-and-glass`, configured by `wrangler.toml`). CI runs `mise run check` (lint
and build) on PRs and on pushes to `main`; the publish step lives in Cloudflare, so CI stays build-only. To deploy from
`main`, give the owner `mise run build && wrangler deploy` — it needs their Cloudflare login. The `workers.dev` account
subdomain is private, so keep it out of tracked files. Full notes:
[CONTRIBUTING.md](./CONTRIBUTING.md#deploy).

## Rules

- Work on a branch and open a PR to `main`.
